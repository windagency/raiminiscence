# hippo-memory 3.3.3 against 3.1.1 on a LongMemEval-S and LoCoMo sample (2026-11-07)

Does hippo-memory 3.3.3 retrieve what 3.1.1 did? If so, the published LongMemEval-S and LoCoMo results, run with 3.1.1 on 2026-11-02, stand for 3.3.3.

Method: hippo-memory's own harnesses, unchanged from `v3.1.1` to `v3.3.3`, run as on 2026-11-02, with the same arms. A is hippo-memory as installed, BM25 only. B adds `@huggingface/transformers` 4.3.0, so it embeds with MiniLM. The sample is LongMemEval-S's first 50 questions (`recall_cli_haystack.py --limit 50`, default and lifted budgets) and LoCoMo's first 2 conversations, 304 QAs (`run.py --conversations 2 --score-mode evidence`, top-k 5, budget 4000). Each sample was run with 3.3.3, then with 3.1.1 again, and both were compared with the 2026-11-02 3.1.1 runs. Memory ids are random per build, so only the ranked sessions (LongMemEval-S) or dialogue ids (LoCoMo) are compared.

| Run | 3.3.3 against 3.1.1 | 3.1.1 again against 3.1.1 |
|---|---|---|
| LongMemEval-S A, default budget | 50 of 50 rankings identical | 50 of 50 |
| LongMemEval-S A, lifted budget | 50 of 50 | 50 of 50 |
| LongMemEval-S B, default budget | 49 of 50 | 49 of 50 |
| LongMemEval-S B, lifted budget | 49 of 50 | 48 of 50 |
| LoCoMo A | 300 of 304, evidence recall 0.5352 against 0.5352 | 296 of 304, 0.5352 against 0.5352 |
| LoCoMo B | 304 of 304, evidence recall 0.5681 against 0.5681 | 260 of 304, 0.5681 against 0.5681 |

No score is identical across any two runs, the same version included: scores move by up to about 1%, which reorders near-ties. 3.3.3 differs from 3.1.1 no more than 3.1.1 differs from itself, and evidence recall is the same to four decimals. That matches the 3.2 and 3.3 release diffs, which touch recall only for captured-note tags, which neither harness writes. So the 2026-11-02 LongMemEval-S and LoCoMo results stand for 3.3.3, and the full runs were not repeated.

Single machine. The drivers and the comparison script are in the benchmark scratch directory, not in the repo.
