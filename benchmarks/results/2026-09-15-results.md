## 2. Invalidation correctness

rAIminiscence: 8/9 scenarios passed. hippo-memory: 5/9 scenarios passed. Reported as pass/fail per scenario, not a fabricated aggregate percentage, given the small scenario count.

| Scenario | Mechanism | rAIminiscence | hippo-memory |
|---|---|---|---|
| webpack-to-vite | commit-message | PASS | FAIL — missed target(s): inv-m02 |
| jest-to-vitest | commit-message | PASS | PASS |
| deprecate-legacyauth | commit-message | PASS | PASS |
| remove-moment | commit-message | FAIL — false-positive bystander(s): inv-b05 | FAIL — false-positive bystander(s): inv-b05 |
| redux-to-zustand | commit-message | PASS | PASS |
| class-components-to-hooks | commit-message | PASS | FAIL — false-positive bystander(s): inv-b08 |
| node-18-to-22 | commit-message | PASS | FAIL — false-positive bystander(s): inv-b09 |
| drop-react-admin | commit-message | PASS | PASS |
| webpack-config-file-changed | file-based | PASS | PASS |

The `remove-moment` scenario is a deliberate known-limitation case (the target string collides with an ordinary English word) included for honesty, not to flatter either system — see `benchmarks/corpus/invalidation-scenarios.json`.

**Caveat:** hippo-memory has no relatedFiles-style file-anchoring concept, so the `webpack-config-file-changed` scenario (rAIminiscence's v2 file-based invalidation) is driven on the hippo side via its one invalidation primitive, `hippo invalidate "<pattern>"`, matching on file-name content instead of on an actual changed-file signal. This conflates two mechanisms rAIminiscence keeps independent (v2 file-based vs v9 commit-message-based) — see `benchmarks/README.md`.
