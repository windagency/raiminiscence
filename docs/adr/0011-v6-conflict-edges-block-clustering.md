# v6 Conflict Edges keep Clustering from merging memories that disagree

[Back to CONTEXT.md](../../CONTEXT.md) • [Back to docs/adr/README.md](README.md) • [Back to hld.md](../architecture/hld.md) • [Back to lld.md](../architecture/lld.md)

Clustering (unchanged since v1) groups Episodic Memories by embedding similarity alone: one Memory seeds a Cluster and every other Memory whose similarity to that seed clears 0.82 joins it, with no other gate anywhere in the mechanism. Promotion then merges a whole Cluster into a single synthesized Semantic Memory. v5's Conflict Detection introduces a case Clustering never anticipated: two Memories can clear that same 0.82 threshold — the same one Conflict Candidate detection itself uses to flag possibly-disagreeing pairs — while also carrying a confirmed `"contradicts"` verdict on their Conflict Edge. Left unmodified, Promotion would silently fold two disagreeing claims into one settled-looking pattern, presenting a resolved synthesis where none exists. This is the same correctness gap ADR-0010 identified and closed for Spreading Activation, surfacing here at Consolidation time instead of Recall time.

We chose to gate Clustering itself: when a candidate's confirmed `"contradicts"` edge is with the seed it would otherwise join, it's excluded from that Cluster — unconditionally, with no config surface — mirroring ADR-0010's non-traversable (not down-weighted) treatment, and for the same reason: a partial down-weight could still be overridden by strong-enough similarity, while an outright exclusion can't be. The check compares a candidate only against the seed it's trying to join, matching Clustering's existing seed-only similarity comparison, rather than against every current member of the forming Cluster. This is a genuine trade-off, not an oversight: it's cheaper and keeps the same shape as the existing algorithm, at the cost of not catching a contradicts edge between two non-seed members who both independently qualified against the seed on their own merits. The gate also only prevents new merges going forward — a Semantic Memory a prior Consolidation run already promoted, before the relevant `"contradicts"` verdict existed, is left exactly as it is; there is no retroactive scan of its `promotedFrom` ids against the Conflict Edge store.

This is the Clustering-side counterpart to ADR-0010's Spreading-Activation-side gate — both stem from v5's Conflict Detection and apply the identical policy (non-traversable/non-mergeable, never merely re-weighted) at their own point of use, but they're independent mechanisms: this gate doesn't touch Co-access Edge or the Recall-time walk, and ADR-0010's gate doesn't touch Clustering or Promotion. A related idea — Feedback (v2) making Promotion resist clusters with a history of negative feedback — was deliberately scoped out of v6 to keep this change to one mechanism, matching the single-mechanism scope of ADR-0008/0009/0010; it remains a candidate for a future version.
