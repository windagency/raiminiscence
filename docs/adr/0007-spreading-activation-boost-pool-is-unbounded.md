# Spreading Activation's boost pool is the full qualifying set, not a bounded window

[Back to docs/adr/README.md](README.md) • [Back to hld.md](../architecture/hld.md)

Recall's Spreading Activation boost ([ADR-0006](./0006-spreading-activation-boost-only.md)) computes each qualifying candidate's boost against every other candidate that cleared `minScore` in the same call — the full qualifying set, not a bounded top-N window by `baseScore`. This was reconsidered during a post-v2 architecture review: bounding the pool would improve precision (a candidate's boost would only draw from memories with a genuine relationship to the query, not merely-trivial ones with `baseScore` just above zero) and cap the O(n²) per-call cost as a store grows. We chose to leave it unbounded because ADR-0001's premise is a small, personal, flat-file store where the whole active set and a bounded window are the same size in practice, and introducing a second tuning constant (a window size, alongside `k` and `minScore`) to solve a problem no real usage has hit yet is exactly the kind of speculative generality worth resisting until there's a concrete case. Revisit if a real store size ever makes the full-set scan's cost or its precision actually bite.
