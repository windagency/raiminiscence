# v2 Spreading Activation boosts existing candidates, never injects new ones

[Back to 0007-spreading-activation-boost-pool-is-unbounded.md](0007-spreading-activation-boost-pool-is-unbounded.md) • [Back to 0008-v3-spreading-activation-can-surface.md](0008-v3-spreading-activation-can-surface.md) • [Back to 0009-v4-spreading-activation-multi-hop.md](0009-v4-spreading-activation-multi-hop.md) • [Back to docs/adr/README.md](README.md) • [Back to hld.md](../architecture/hld.md)

Recall's v2 Spreading Activation mechanism (Co-access Edges, strengthened whenever two Memories co-occur in the same `recall`'s result set) only adds a bonus term to a candidate that already independently cleared similarity × Strength × Confidence Tier weight filtering — it never surfaces a Memory whose only path into the results is a graph connection, with zero independent match to the query. This is narrower than what "spreading activation" usually means in the reference literature (and in the original Valora Memory talk this project draws from), where activation can discover new nodes a pure similarity search would never surface on its own. We chose the conservative, boost-only version for v2 because candidate-injecting retrieval is a bigger, less predictable behaviour change — a query could return a Memory with no textual or semantic relationship to it at all, purely because of a graph link — and that's deferred as a possible future revisit once the simpler boost-only mechanism is proven in practice, mirroring how the whole graph layer itself was deferred out of v1 by [ADR-0002](./0002-v1-retrieval-excludes-spreading-activation.md).
