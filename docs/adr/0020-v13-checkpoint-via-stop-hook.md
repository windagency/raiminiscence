# v13 adds a `checkpoint` Memory Kind, refreshed periodically via the `Stop` hook rather than written once at session end

[Back to CONTEXT.md](../../CONTEXT.md) • [Back to 0023-v18-fix-nudge-via-post-tool-use-hook.md](0023-v18-fix-nudge-via-post-tool-use-hook.md) • [Back to 0025-v19-opportunistic-consolidation-debounce.md](0025-v19-opportunistic-consolidation-debounce.md) • [Back to docs/adr/README.md](README.md) • [Back to flows.md](../architecture/flows.md) • [Back to hld.md](../architecture/hld.md) • [Back to lld.md](../architecture/lld.md) • [Back to developer-guide.md](../developer-guide.md) • [Back to user-guide.md](../user-guide.md) • [Back to packages/raiminiscence-hooks/README.md](../../packages/raiminiscence-hooks/README.md)

Per-Turn Auto-Recall (v10) and SessionStart Overview priming both surface Memories that independently rank well by similarity or Strength — neither answers "what was I in the middle of?" across a session boundary. This was flagged as an independent backlog candidate after v11 (team-shared memory) and v12 (Reinforcement Ceiling); no further scoping existed for it before this design session.

The obvious mechanism — synthesize a summary automatically when a session ends — turned out not to be mechanically available. rAIminiscence's server has no LLM of its own (only an embedding-model client); every Memory's content is authored by the calling agent via `remember`. Investigating the three supported clients' hooks surfaced a hard constraint: `SessionEnd` (Claude Code), `sessionEnd` (Cursor), and Codex CLI's equivalent all fire strictly post-hoc, with no path back to the model — pure fire-and-forget cleanup. The only hook that *can* cause the agent to take one more action is `Stop`/`stop` (fires when the agent finishes a turn, can block with a reason and get one more turn including a tool call) — but it fires on every ordinary turn-end throughout a session, with no signal distinguishing "the agent just paused" from "this is genuinely the last turn." There is no hook, on any of the three clients, that both knows the session is truly ending and can still nudge the model.

## Decision

**Reframe from "one write, at the true end" to periodic checkpointing.** Debounce a soft nudge on `Stop`/`stop` to fire at most once per 15 minutes or 20 turns of a session, whichever comes first. "Current focus" becomes "whatever the most recent checkpoint says," regardless of when it was written — which also means a crash or an ungraceful exit loses nothing, where a true end-of-session design would lose everything. The alternative considered — keep nudging on every `Stop` and rely on the client's own loop-guard (Claude Code's block-cap, default 8; Cursor's `loop_limit`, default 5) to eventually stop re-triggering — was rejected: it doesn't produce an honest "end" signal either, it just fires more often and calls whichever write happened to land last "the end."

**New Memory Kind: `checkpoint`.** Base Half-life 3 days — shorter than Episodic's 7, since each new Checkpoint instantly obsoletes the last one for the lookup that matters, and a stale one should clear the Pruning threshold (0.05) sooner than a raw observation would. Rejected alternative: reuse Episodic Memory with an `isCheckpoint` flag. Rejected because a Checkpoint is structurally different from an observation — it's a continuity pointer, not something Clustering should ever consider or Promotion ever build on — and every future Episodic-specific rule would otherwise have to remember to special-case it. Being its own Kind, a Checkpoint is automatically outside Clustering's and Promotion's candidacy: both steps only ever operate on Episodic Memories to begin with, so this needed no new exclusion logic. Conflict Candidate detection is different — it isn't Kind-scoped, operating on whatever Kinds a `recall` call's Scope/`kind` filtering already resolved to — so it gets an explicit new exclusion: a Checkpoint is never flagged as a Conflict Candidate with anything, since successive Checkpoints on the same evolving task are expected to be near-duplicates by construction, not a genuine disagreement. A Checkpoint otherwise remains an ordinary `recall` candidate.

**The nudge is a soft suggestion, never enforced.** When the debounce threshold crosses, the hook injects a suggestion to call `remember` with `kind: "checkpoint"`; if the agent doesn't act on it, nothing re-blocks until the next threshold crossing. Rejected alternative: block until compliance (relying on the same loop-guards as above). Rejected because nothing else in this project currently forces agent compliance with an injected instruction — Per-Turn Auto-Recall and SessionStart priming both inject and let the agent decide — and enforcing it here would be a new, more coercive precedent with a real downside: a legitimate `Stop` (e.g. the agent genuinely finished and is waiting on the user) getting blocked repeatedly against the user's own flow.

**Client scope: Claude Code and Cursor only.** Codex CLI's `Stop`-hook continuation is on OpenAI's own public roadmap tracker but explicitly flagged as not reliable yet as of this writing (a live bug shows it sometimes failing to dispatch at all in app-server mode). This is the same shape as [ADR-0015](0015-v10-per-turn-auto-recall-excludes-cursor.md)'s Cursor exclusion for Per-Turn Auto-Recall — a genuine per-client capability gap, not a workaround to design around. Codex picks this up automatically once/if its `Stop` hook hardens.

**Retrieval: extend `overview`, no new MCP tool.** `overview`'s response gains a `currentFocus` field: the calling writer's own most recent Checkpoint, and — when [Shared Memory](0017-v11-shared-memory-via-git-worktree.md) makes them different — the project's most recent Checkpoint overall. Both are fetched by recency, not Strength (this is a distinct lookup, not a rank-ordering exemption within the existing top-N), and are additive to Overview's existing top-N-by-Strength results rather than displacing any of them. Per-writer scoping reuses the `writer` field [ADR-0018](0018-v11-shared-memory-writer-identity.md) already added; in the default non-shared case there is only ever one writer, so the two lookups are always identical and this adds no visible complexity for the common case. Rejected alternative: a new dedicated tool (e.g. `resume`). Rejected because this project has consistently grown existing tools rather than multiplying the MCP surface — `overview` already gained `conflictsWith` in v5 without becoming a new tool — and a new tool would mean the `SessionStart` hook has to learn to call two things instead of one for no corresponding benefit.

Fixed constants throughout (3-day Half-life, 15-minute/20-turn debounce), no project-config surface — consistent with every decay/threshold constant in this project except Spreading Activation's `maxHops`, which earned its config surface from a documented, real per-project tradeoff ([ADR-0009](0009-v4-spreading-activation-multi-hop.md)) that nothing here has an equivalent for yet.

This is a design decision only; implementation (the schema addition, the hooks-package `Stop`/`stop` handlers, the `overview` change, and tests) is deliberately left to a separate, dedicated pass — mirroring how v11 and v12 were each designed in one session and implemented in a later one.
