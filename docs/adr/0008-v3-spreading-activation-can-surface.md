# v3 Spreading Activation can surface a candidate, not just boost one

[Back to 0009-v4-spreading-activation-multi-hop.md](0009-v4-spreading-activation-multi-hop.md) • [Back to docs/adr/README.md](README.md) • [Back to hld.md](../architecture/hld.md)

[ADR-0006](./0006-spreading-activation-boost-only.md) made Spreading Activation boost-only for v2: a Co-access Edge could only add a bonus to a candidate that already independently qualified on similarity × Strength × Confidence Tier weight, never surface one that didn't. v3 partially revises this: a candidate with no independent qualifying match can now surface if it has a Co-access Edge at or above a fixed weight floor (≥ 4, i.e. co-recalled with a qualifying candidate at least twice) directly to a candidate that did independently qualify. We're loosening *eligibility*, not *ranking discipline* — a surfaced-only result is still computed from the same edge-weight mechanism as the existing boost, rebased so it can never outrank a genuine match, and it must connect directly to an independently-qualifying candidate rather than to another surfaced-only one, so the mechanism stays exactly one hop and cannot chain into de facto multi-hop retrieval. We chose to revisit ADR-0006 now, rather than leave it in place indefinitely, because the boost-only mechanism has been in production use since v2 with no reported false-positive problem from loosening it this specific, narrow way — and because the alternative (a fully unconstrained candidate-injecting mechanism, the version ADR-0006 originally set aside as "a bigger, less predictable behaviour change") is explicitly still deferred, not adopted. Multi-hop or chained surfacing remains out of scope, banked for v4+, mirroring how ADR-0006 itself staged boost-only before this revision.
