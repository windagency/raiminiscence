# v5 Conflict Edges make a Spreading Activation edge non-traversable, not just re-weighted

[Back to docs/adr/README.md](README.md) • [Back to hld.md](../architecture/hld.md)

ADR-0006 through ADR-0009 all treat a Co-access Edge's weight and distance as the only gates on whether Spreading Activation's boost and surfacing walk it — clear the eligibility floor at the right distance, and the edge is walked, with no other veto anywhere in the mechanism. v5's Conflict Detection introduces a case those ADRs never anticipated: an edge whose weight and distance both clear every existing threshold, yet whose two endpoints have been confirmed, by an agent, to actively disagree with each other. Walking that edge for boost or surfacing purposes would let two contradicting claims mutually reinforce each other's ranking — the exact opposite of what a strengthened Co-access Edge is supposed to signal (two Memories proving useful together) — and would be a correctness gap this feature introduces into existing v2–v4 machinery, not a neutral non-interaction.

We chose to make a confirmed `"contradicts"` Conflict Edge non-traversable — skipped entirely during the walk, before any existing eligibility-floor or hop-decay arithmetic runs — rather than leave Spreading Activation unmodified or merely down-weight such an edge. A partial fix (e.g. a penalty factor on a contradicting edge's contribution) would still let a strong-enough edge win out at some weight, reintroducing the same problem at a higher threshold; an outright non-traversable rule needs no new tunable and can't be quietly defeated by two Memories that keep getting recalled together. We left Co-access Edge's own strengthening completely unaffected — only the consumption side, inside Spreading Activation's walk, changes — because co-occurring in the same `recall` result reflects proximity/relevance to a query, not agreement, so the underlying weight is still valid bookkeeping even between two Memories that turn out to disagree.

This is a partial revision of ADR-0006/0007/0008/0009, the same way ADR-0009 was itself a partial revision of the ADRs before it: every existing invariant (the escalating eligibility floor, the hop-decay arithmetic, strictly-monotonic-by-distance ranking, the visited-set bound) stays exactly as those ADRs describe. v5 adds exactly one new gate, checked before any of that math runs, for whether an edge may be walked at all.
