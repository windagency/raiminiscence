# Team/agent-shared memory becomes a legitimate future direction; ADR-0003 is flagged for eventual supersession, not superseded here

[Back to CONTEXT.md](../../CONTEXT.md) • [Back to docs/adr/README.md](README.md) • [Back to hld.md](../architecture/hld.md) • [Back to NEXT_STEPS.md](../../NEXT_STEPS.md)

A 2026-09-15 internal comparison against hippo-memory, plus the empirical benchmarks in `benchmarks/`, prompted a deliberate re-examination of rAIminiscence's own vision, not just a feature-parity check. The conclusion: rAIminiscence's scope no longer holds single-developer/single-agent/single-project as a hard ceiling. Multiple humans and/or multiple agent instances sharing one project's memory store — "team/agent-shared memory" — is now a genuine, in-scope future direction. This directly contradicts ADR-0003's stated rationale for staying stdio-only ("a hosted/shared HTTP or SSE server (e.g. for team-shared memory)... is explicitly out of scope for this project rather than a deferred v2 feature"), so it's recorded here rather than silently overridden.

This ADR does not itself supersede ADR-0003. No transport, storage, or concurrency mechanism for team/agent-shared memory has been designed; stdio-only MCP remains the transport in effect until a dedicated design session picks one. Two constraints are fixed now for whatever that design turns out to be: (1) team/agent-shared memory (multiple humans/agents on *one* project) is the near-term shape to pursue; a further, later evolution toward hosted/SaaS multi-tenancy (many tenants behind API-key auth, analogous to hippo-memory's HTTP+webhook+dashboard surface) is deliberately sequenced after it, not designed concurrently with it. (2) ADR-0001's flat-file, zero-infrastructure core storage is non-negotiable — any team-shared or multi-tenant mechanism must be built as an opt-in additional layer on top of it, never a replacement (e.g. no migration to a database as a precondition).

**Resolution (2026-09-16):** the dedicated design session happened and shipped as v11 ([ADR-0017](0017-v11-shared-memory-via-git-worktree.md), [ADR-0018](0018-v11-shared-memory-writer-identity.md)). The flagged tension resolved *without* contradiction, not via supersession: team/agent-shared memory turned out not to need a hosted HTTP/SSE transport at all — it propagates over git instead — so ADR-0003's actual decision (stdio-only MCP, no hosted transport) was never violated and stands unchanged. Only the misleading parenthetical in ADR-0003's own rationale (which implied team-shared memory would require a hosted transport) needed correcting, and has been. Both locked constraints above held throughout: sequencing was respected, and no database migration was required.
