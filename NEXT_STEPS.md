### At least as good as hippo-memory, in quality and performance

Measured against hippo-memory 3.1.1 on 2026-11-02 ([`benchmarks/README.md`](benchmarks/README.md)): rAIminiscence leads on LongMemEval-S all-evidence R@5 (+4.0 [+1.9, +6.4]), LoCoMo evidence R@5 (+2.6 [+1.5, +3.7]) and invalidation (8 of 9 against 5 of 9). It trails on the per-turn hook (226 to 270 ms with a server running and 670 to 980 ms without, against 143 ms at 1,500 Memories), on write cost, and on this repo's own 20-query corpus (Recall@5 80.0% against 82.5%). Re-run against hippo-memory 3.3.3, the latest release, on 2026-11-07: the corpus and invalidation scores are unchanged, and with ADR-0039 to ADR-0041 built rAIminiscence is faster on the hook (106 to 126 ms against 239 to 241 ms) and on writes (2.2 to 2.7 ms against 2.7 to 3.1 ms). On a LongMemEval-S and LoCoMo sample, 3.3.3 retrieves what 3.1.1 did, within 3.1.1's own run-to-run drift, so the 2026-11-02 results stand (`benchmarks/results/2026-11-07-hippo-3.3.3-retrieval-sample.md`). The full gate against hippo-memory 3.5.1 on 2026-11-11 confirms it at a load of 1 to 7: the same corpus and invalidation scores, the hook at 53 to 58 ms against 126 to 128 ms, writes at 5.3 to 5.8 ms against 6.5 to 6.9 ms, and one gate check failing, LongMemEval-S any-evidence R@1 against arm B. With nomic's task prefixes ([ADR-0042](docs/adr/0042-nomic-embeddings-carry-their-task-prefixes.md)), the gate re-run on 2026-11-12 passes all 28 checks, and corpus Recall@5 rises to 85.0%, ahead of hippo-memory's 82.5%. Every item below keeps what distinguishes rAIminiscence: flat Markdown and YAML storage, stdio-only MCP, bounded decay and reinforcement, both invalidation paths, conflict detection and the Promotion Audit, and Shared Memory over git. A fix that needs a database or a network service is out of scope.

- [ ] **A benchmark gate that defines "at least as good".** On every public benchmark, the lower bound of the paired 95% interval for rAIminiscence minus hippo-memory stays at or above -3 points on every reported metric, and hook latency stays at or below hippo-memory's median at each store size. One script runs the corpus, extended, LongMemEval-S (any- and all-evidence) and LoCoMo suites against the latest hippo-memory release, following the plans on [hippo-memory.com/benchmarks](https://hippo-memory.com/benchmarks/). Run it on each hippo-memory release and each rAIminiscence ranking change. Built on 2026-11-09 as `benchmarks/benchmark-gate.ts`, not merged. First full run on 2026-11-11 against hippo-memory 3.5.1 ([`benchmarks/results/2026-11-11-benchmark-gate.md`](benchmarks/results/2026-11-11-benchmark-gate.md)): it fails one check of 28, LongMemEval-S any-evidence R@1 against arm B, -1.2 [-3.6, +1.2]. The hook passes at every store size, 52.9 to 57.5 ms against 126.2 to 128.1 ms. The floor was -1 point until 2026-11-10. With about 500 questions, a dead heat on R@1 has a lower bound near -2.4 points, so -1 asked for a lead of about 1.5 points, not parity. Scored by it, the published runs still fail on one metric: rAIminiscence's default Embedded build against hippo-memory 3.1.1 B trails on LongMemEval-S any-evidence R@1 by -1.2 [-3.6, +1.2]. Every other metric passes. Re-run on 2026-11-12 with ADR-0042 built, it passes all 28 checks ([`benchmarks/results/2026-11-12-benchmark-gate.md`](benchmarks/results/2026-11-12-benchmark-gate.md)). Since 2026-11-10 a hook call that returns no context, which is how the hook reports a recall that failed or timed out, stops the hook suites instead of being timed: a stalled run on a saturated machine had scored 55 of them. Each step now waits for the load average to drop to the core count, and a command silent for 90 minutes is killed with its workers and its step retried once. Check once merged and passing.

Built per [ADR-0042](docs/adr/0042-nomic-embeddings-carry-their-task-prefixes.md) on 2026-11-12, not merged; prefixed vectors cluster at 0.87. The ADR's acceptance holds. Check once merged.
- [ ] **Re-run rAIminiscence's LongMemEval-S arms on the current build.** The published OD and ED arms predate ADR-0034 to ADR-0038. Fresh store copies per recall should leave rankings unchanged. Verified for ED on 2026-11-11: the gate's fresh Embedded run gives the same top 10, in the same order, on all 500 questions. OD is not re-run.
- [ ] **Measure hippo-memory's large-store LongMemEval variant.** All 19,195 sessions in one store, where hippo-memory reports R@5 of 47.2% with MiniLM. rAIminiscence has never been measured at that scale, and recall scans every Memory.
- [ ] **The hook asks the running server for the whole recall, not just the embed.** Builds on [ADR-0038](docs/adr/0038-a-running-server-keeps-the-embedded-model-warm-for-short-lived-callers.md)'s socket: the hook sends its prompt and gets back the finished context, falling back to local recall. In-process recall is about 21 ms, so the hook would cost Node startup, its import and the socket round trip, flat in store size. Built per [ADR-0039](docs/adr/0039-the-per-turn-hook-asks-a-running-server-for-the-whole-recall.md) on 2026-11-03, not merged. Target met: interleaved with hippo-memory's hook call by call, 50 to 58 ms against 121 to 125 ms at every store size, faster in all 126 pairs (`benchmarks/results/2026-11-03-hook-latency-interleaved.md`). Check once merged.
- [ ] **Cut the hook's import cost** (about 63 ms): load only the socket client, and import the engine only on fallback. Built as part of [ADR-0039](docs/adr/0039-the-per-turn-hook-asks-a-running-server-for-the-whole-recall.md), not merged. Measured on 2026-11-06: the shim and the recall client import in about 15 ms, against about 63 ms for the engine, which now loads only when no server answers. Check once merged.
- [ ] **Close the no-server gap** (600 to 760 ms, mostly the Embedded model load). Decided on 2026-11-03: the hook starts a short-lived warm process that serves both sockets and exits after 30 idle minutes, over a smaller quantised model. Built in [ADR-0040](docs/adr/0040-the-hook-starts-a-warm-process-when-no-server-runs.md), not merged; the ADR says why it is not the sync daemon rejected below. Target met on 2026-11-03: from the second prompt on, 50 to 58 ms against hippo-memory's 123 to 126 ms, faster in all 126 interleaved pairs, with a first-prompt cost of 3 to 18 ms. Check once merged.
- [ ] **Find what grows with store size on the warm hook path** (109 ms at 10 Memories, 270 ms at 1,500). Likely each process reading every Memory file; check whether [ADR-0021](docs/adr/0021-v14-versioned-disk-cache-for-recall-latency.md)'s on-disk cache covers the hook. Moot if the whole-recall item lands: with it built, the served hook took 54 to 84 ms from 10 to 1,500 Memories on 2026-11-06, with no trend in store size. Check once that item merges.
- [ ] **Cut write cost.** `remember` through the running MCP server took 33 to 35 ms against hippo-memory's 3 to 5 ms on 2026-11-06, almost all of it the embed and two `git config` calls. Built in [ADR-0041](docs/adr/0041-the-mcp-server-answers-remember-before-the-embed.md), not merged: the server answers once the Memory is on disk and writes its vector after, as hippo-memory does. Target met on 2026-11-07: 3.7 to 5.0 ms against 4.7 to 5.2 ms, rAIminiscence's median at or below at every store size (`benchmarks/results/2026-11-07-write-latency-interleaved-adr-0041.md`). Check once merged.
- [ ] **Grow the hand-labelled corpus to at least 100 coding-agent queries, labelled before any tuning.** 20 queries cannot separate ADR-0032's corpus regression (four queries lose one relevant Memory each) from noise.
- [ ] **Revisit the fusion weight only with held-out validation.** Tune on one of the corpus, LongMemEval-S and LoCoMo, and hold out the other two, the discipline the co-access work used with Flask and Hono. Never trade a public benchmark for the corpus.
- [ ] **An opt-in local cross-encoder reranker over the top 40.** hippo-memory now ships one, plus a hosted reranker. Opt-in because it costs latency.
- [ ] **Per-turn indexing, if hippo-memory ships it into `hippo recall`.** Its turn-level hybrid scripts reach 86.8 to 88.5% all-evidence R@5, which would erase rAIminiscence's LongMemEval-S lead. Watch on each hippo-memory release. Not in 3.2.0 to 3.3.3, checked on 2026-11-07: those releases change capture, rules and migration, not recall. Not in 3.4.0 to 3.5.1 either, checked on 2026-11-11: they refactor the superseded check and add an opt-in hook tag filter.
